# qt-dep

Toy knowledge base for the quality-tracking prototype (plays the role of
vws-data). `kb.json` holds a knowledge quality per topic; `qt-app` reads it
through `QT_COMPONENT_DATA_PATH`. Lowering a value makes answers on that topic
fail more often, which is how a data regression is simulated.

`traces.jsonl` holds the answer-quality cases as simulated Langfuse traces, one
per line (generated by `scripts/make_traces.py`). qt-app replays each trace's
`input` and expects its `output`; the trace `id` is the case's identity, and
`metadata` carries the topic and the pass rate at full quality (`base_p`).
Editing a trace changes that case's definition: it is reported as edited, not
compared with its past.

Changes to this README do not affect quality; they still create a new state.
